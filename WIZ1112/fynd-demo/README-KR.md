## 개요

FYND는 한국 독립 브랜드 패션을 위한 크로스모달 검색 엔진입니다. 맞는 키워드를 추측하는 대신, 원하는 걸 묘사하면 가장 가까운 상품을 찾아줍니다.

검색 방식은 세 가지입니다.

- **텍스트** — "다이아 퀼팅이 들어간 검은색 후드 패딩"
- **이미지** — 사진을 올리면 시각적으로 비슷한 상품을 찾아줌
- **텍스트 + 이미지** — 사진을 기준으로 잡고 말로 방향을 잡아줌

모든 상품은 이미지·텍스트 임베딩으로 색인되고, 쿼리는 벡터 비교로 응답됩니다. 랭킹은 상품명을 전혀 읽지 않는데, 이것이 묘사형 검색을 가능하게 하는 지점입니다.

**라이브 데모: https://wiz1112-fynd-demo.hf.space**

## 왜 FYND인가

쇼핑 검색은 태그와 카테고리 필터를 중심으로 만들어져 있고, 옷의 실제 생김새로 검색하려는 순간 무너집니다.

- 같은 표현이라도 브랜드마다 실제 옷이 다릅니다. 어떤 브랜드의 "루즈핏"은 다른 브랜드의 오버사이즈 실루엣이고, 하나의 필터 값이 이걸 전부 뭉갭니다.
- 상품명은 정작 중요한 디테일(소재감, 드레이프, 플리츠가 꺾이는 모양, 밑단이 얼마나 크롭됐는지)을 담지 못합니다. 그 정보는 사진 안에 있는데, 이름 기반 검색은 그걸 버립니다.
- 이런 브랜드를 모아 파는 플랫폼조차 그런 디테일로 검색해주지 못하니, 빈틈이 실제로 존재합니다.

쓸모 있는 신호가 이미지에 있으니, FYND는 이미지로 랭킹합니다.

데이터의 경우, 대형 플랫폼은 크롤링할 수 없어서(robots.txt가 금지) 브랜드 자사몰을 직접 크롤링했습니다. 한국 도메스틱 브랜드를 고른 건 제가 이 브랜드들을 좋아하기 때문이기도 하고, 바로 이 디테일이 중요하고 기존 검색이 부족한 케이스이기 때문이기도 합니다.

## 기능

**텍스트, 이미지, 또는 둘 다.** 상품을 묘사하거나, 참고 사진을 올리거나, 둘을 섞습니다. "oversized double-breasted wool coat in camel"을 넣으면 세 브랜드의 카멜 코트가 오직 이미지 유사도로 랭킹되어 나옵니다.

![텍스트 검색 결과](assets/ui_results_text.png)

사진을 더하면 두 신호를 섞어 검색합니다. "belted wool coat"에 코트 사진을 얹으면 원본 상품까지 포함한 벨티드 발마칸 실루엣이 올라옵니다.

![텍스트 + 이미지 결과](assets/ui_results_image.png)

**Refine.** "lighter blue", "조금 더 크롭되게" 같은 상대적 표현으로 결과를 그 방향으로 밀어줍니다. 새로 검색을 시작하지 않고요.

**Not for me.** 마음에 안 드는 상품을 숨기면 시각적으로 비슷한 것들도 결과에서 함께 빠집니다.

**위시리스트.** 마음에 든 상품을 담아둡니다.

![위시리스트](assets/ui_wishlist.png)

인터페이스는 영어 우선입니다. 검색 모델이 영어 쿼리를 전제하기 때문입니다.

## 작동 방식

![FYND 파이프라인](assets/pipeline.png)

1. **크롤링.** 29개 브랜드 자사몰(모두 Cafe24 플랫폼)을 SQLite 카탈로그로 크롤링합니다. 각 사이트의 robots.txt를 지키고 요청 사이에 딜레이를 뒀습니다. 상세는 Open Graph 메타데이터에서 파싱하고, 이미지는 해시로 중복 제거 후 500px로 리사이즈합니다.
2. **분류.** SigLIP2가 사이트의 제각각인 메뉴 대신 이미지에서 각 상품의 카테고리를 라벨링합니다. 제로샷 2단계(대분류 → 세부)입니다.
3. **임베딩.** FashionCLIP 이미지·텍스트 임베딩과 EmbeddingGemma 상품명 임베딩을 한 번 미리 계산해 캐싱합니다.
4. **랭킹과 서빙.** FashionCLIP이 쿼리를 상품 사진과 같은 공간으로 임베딩합니다. 텍스트만 있는 쿼리는 텍스트→이미지 유사도로 직접 랭킹하고, 텍스트+이미지 쿼리는 네 신호를 Reciprocal Rank Fusion으로 결합합니다. 브랜드별 상한으로 결과를 다양하게 유지합니다. **Refine**는 정제 문구를 스티어링 벡터로 쿼리에 더하고, **not for me**는 비슷한 상품에 유사도 페널티를 겁니다. 전체는 Docker Space 위 Flask 앱으로 돌아갑니다.

## 랭킹 모델 선택

핵심 질문은 상품명으로 랭킹할지, 이미지로 랭킹할지였습니다. 이름 기반 텍스트 매칭과 크로스모달 텍스트→이미지 랭킹을 비교했는데, 답은 사람들이 어떻게 검색하느냐에 달려 있었습니다.

![키워드형 vs 자연어형 쿼리 성능](assets/eval_query_style_flip.png)

- **짧은 키워드 태그**("shoes gray")에서는 이름 매칭이 좋아 보입니다. 그 단어들이 상품명에 그대로 들어 있기 때문입니다.
- **자연어 묘사**에서는 이름 매칭이 무너지고 텍스트→이미지가 버팁니다 (MRR 0.48 vs 0.12).

실제 사용자는 원하는 걸 묘사하지 SKU식 태그를 치지 않으므로, FYND는 텍스트 전용 쿼리를 크로스모달 텍스트→이미지로 랭킹합니다. 사진이 함께 주어지면 두 입력을 모두 쓰도록 네 신호를 결합합니다. 크로스모달 랭커 위에 더 무거운 융합을 얹어봐도 실험에서 통계적으로 의미 있는 개선이 없었기에, 더 단순한 구성을 서빙합니다.

## 로컬 실행

Python 3.11이 필요합니다. 데이터베이스와 미리 계산한 임베딩은 Git LFS로 관리됩니다.

```bash
git clone https://huggingface.co/spaces/WIZ1112/fynd-demo
cd fynd-demo

python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python app.py
# http://localhost:5001 접속
```

첫 쿼리는 모델이 로드되는 동안 몇 초 걸리고, 이후로는 빠릅니다. 배포와 동일하게 실행하려면:

```bash
docker build -t fynd .
docker run -p 5001:5001 fynd
```
