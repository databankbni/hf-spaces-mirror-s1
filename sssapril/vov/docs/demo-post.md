## 1. Demo 简介

**vov** 是一个**通用的多 Agent 群聊协作平台**。用户扮演"导演"角色，创建项目、定义 AI 角色（Agent），把它们编排进群组，让多个 AI 在群聊中像真实团队一样协作——可以互相 @、分工、推进任务、产出可交付的成果。

- **产品形态**：Web 应用（同时支持桌面端打包）
- **核心用户**：想用 AI 搭建"小团队"的创作者 / 研究者 / 写作者 / 玩法的开发者
- **三大核心亮点**：

  - **群任务机制**：群组内任务串行执行、跨群任务通过订阅自动衔接，AI 像真实团队一样按节奏推进
  - **`render_view` 渲染引擎**：9 种可视化视图（表格 / 列表 / 树形 / 文档 / 卡片 / 统计 / 时间线 / 地图 / 图谱），让 AI 的产出不再是纯文字
  - **模板生态**：内置小说写作 / 狼人杀等开箱即用模板，支持项目一键导入导出，让用户和社区共享玩法

## 2. Demo 创作思路

**灵感来源**：现有 AI 工具大多处在两个极端——单聊式 AI 助手自由但缺乏团队感，固定式 Workflow 稳定但无法即兴发挥。我们想做的是**两者之间的通用平台**：把"多 Agent 协作"做成一套通用机制，用户在这个机制上自行定义玩法，可以严格、可以自由、可以两者混合。

**想解决的问题**：
- 复杂任务（写作 / 研究 / 团队决策）单 Agent 难以胜任，多 Agent 协作又缺乏通用框架；
- 固定工作流一旦偏离预设就失效，无法应对"边聊边调整"的真实场景；
- AI 的输出形态单一，结构化数据只能以纯文字呈现，缺少可视化表达；
- 玩法难以复用，每个用户都得从零搭建 Agent 和流程。

**为什么做这个方向**：我们认为 Agent 时代最有价值的不是"更强的单 Agent"，而是"可被编排的 AI 团队"。vov 提供三层通用能力：

- **机制层**：Agent / Group / Task / Chain / Skill / Tool / Memory，把多 Agent 协作抽象成可配置的积木；
- **表达力层**：`render_view` 通用渲染引擎（9 种视图）+ 地图编辑器，让 AI 的输出天然带有结构化展示能力；
- **生态层**：模板 + 项目包导出导入，让好用的项目结构可以一键复用、跨用户分享。

用户通过项目结构决定自由度——约束多就是工作流，约束少就是自由协作。同一套引擎可以承载狼人杀 / 小说写作 / 酒馆跑团 / 论文协作 / 产品设计等任意需要"多个 AI 一起干活"的场景。

## 3. 核心亮点详解

### 3.1 群任务机制：让 AI 像真实团队一样协作

- **群内任务串行执行**：同一群组内同时刻只允许 1 个 `in_progress` 任务，避免多 Agent 抢资源、上下文互相干扰；
- **跨群任务自动衔接**：通过通用订阅机制（`create_subscription` / `query_subscriptions`），上游群任务完成时自动触发下游群任务激活，整条工作流像流水线一样自然推进；
- **任务有交付物**：每个任务都必须有 deliverable（可交付的产物）才能标记为 `done`，杜绝"空完成"的虚假进度；
- **实战示例**：内置「小说写作」模板配置了 8 个群组、共 27 个任务，AI 按"灵感孵化 → 大纲 → 人物 → 分章 → 写作 → 校对 → 出版"等阶段串行推进，单群内任务一一执行，跨群之间通过订阅自动唤醒下一阶段。

### 3.2 `render_view` 渲染引擎：AI 的产出天然可视化

AI 在群聊中可通过 `render_view` 工具直接输出结构化数据，前端实时渲染为可视化面板——

| 视图类型 | view_type | 适用场景 |
|---------|-----------|---------|
| 表格 | `table` | 列表数据、对比数据、结构化记录 |
| 列表 | `list` | 卡片列表、成员列表、资源目录 |
| 树形 | `tree` | 目录结构、层级关系、组织架构 |
| 文档 | `document` | 长文内容、报告、故事正文 |
| 卡片 | `card` | 信息卡片、特性展示、对比 |
| 统计 | `stat` | 数据概览、指标面板、进度统计 |
| 时间线 | `timeline` | 事件序列、剧情时间线、历史年表 |
| 地图 | `map` | 空间布局、世界地图、场景关系图（支持六边形/方格网格、领地、子地图下钻） |
| 图谱 | `graph` | 任务流水线、Agent 协作图、知识图谱（通用 DAG） |

- **图谱是双向的**：同一份 DAG 数据既渲染给用户看，也供 Agent 读回作为流程描述，让"流程可视化"和"AI 理解流程"共享同一个数据源；
- **数据源灵活**：支持内联 `data`（一次性数据）和 `data_source`（按需调用后端 API + 定时刷新），复杂项目可以做到"实时刷新的任务看板"；
- **配套地图编辑器**：方格/六边形网格、领地系统、子地图层级嵌套，适合小说世界 / 桌游地图 / 组织架构等空间类信息。

### 3.3 模板与项目包生态：让好用的项目一键复用

- **内置开箱即用模板**：
  - 📖 **小说写作**：8 个专属 Agent + 8 套写作 Skill + 8 个群组 + 27 个任务，目标 50 万字长篇（约 200 章 × 2500 字），覆盖从灵感孵化到出版准备的全流程；
  - 🌙 **狼人杀**：标准 5 人局（2 狼人 + 预言家 + 女巫 + 猎人/村民），用任务隔离身份，主群只发公开信息，私有信息走独立任务链；
- **项目包导出/导入**：用户把"项目 + Agent + 群组 + 资源 + Skill"打包成 `.zip` 项目包，分享给其他人即可一键还原完整玩法；
- **引导 Agent**：用户描述"我想做什么"，引导 Agent 帮忙生成完整项目结构（Agent / 群组 / 任务 / Skill 全套），从空白到完整项目只需一句话。

## 5. TRAE 实践过程

整个项目使用 **TRAE IDE** 开发，核心代码栈：Python FastAPI + React 19 + TypeScript + SQLite，自研 `agentflow` SDK 作为 Agent 执行引擎。

**开发流程概览**：

1. **用 TRAE 从零搭建项目骨架**：后端 FastAPI、前端 Vite + React、数据库用 SQLite，并通过 TRAE 的多轮对话完成初始目录结构、依赖配置和 CI 脚本。
2. **自研 agentflow SDK 核心链路**：和 TRAE 一起设计 `InfoPacket` 流转、`Chain` 隔离、插件化 processor 架构，实现多 Agent 群聊的上下文管理、任务切换和工具调用闭环。
3. **群任务 + 订阅机制**：通过 TRAE 实现群内任务串行锁、跨群订阅触发、deliverable 校验等核心工程问题，落地"AI 团队"协作的真实节奏。
4. **`render_view` 渲染引擎**：通过 TRAE 编写 9 种视图组件、地图编辑器和 RenderSpec 协议，让 AI 输出的结构化数据实时渲染为 UI 面板。
5. **模板系统 + 项目包**：通过 TRAE 抽象项目包 schema、设计模板市场和引导 Agent，实现玩法的复用与分享。
