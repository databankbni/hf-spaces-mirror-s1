# AgentFlow - 多Agent群聊协作平台需求文档

> **v2 状态说明**：本文档描述整体功能需求。v2 架构升级（详见 `docs/v2-design.md`）对部分设计做了调整：
> - 系统层 `auto_continue` / `auto_track` 已删除，改为 Agent 自主调控
> - 资源组织改为树形文件夹
> - 流程推进从系统硬编码改为 Agent 按 skill 自主执行
> - 本文档中涉及上述内容的部分以 v2-design.md 为准
>
> **相关文档**：`docs/v2-design.md`（架构设计）、`docs/architecture/`（技术细节）、`DEVELOPMENT_PLAN.md`（当前执行计划）

## 1. 产品定位

AgentFlow是一个**多Agent群聊协作创作平台**，用户作为"导演"，通过创建项目、组织群聊、配置Agent，让多个AI Agent协作完成复杂创作任务（如小说写作、报告生成等）。

### 核心理念
- **系统提供机制，策略交给Agent和用户**
- Agent通过提示词、skill、工具定义行为，系统不硬编码流程
- 内容格式对Agent读写友好（Markdown + 元数据），人类可视化是渲染层
- 用户有控制权，可选择自动化程度

---

## 2. 用户体系

### 2.1 当前版本
- **单用户个人工作台**模式
- 用户是所有项目的拥有者和管理者
- 用户可在群聊中参与讨论

### 2.2 扩展预留
- 群聊模式设计上支持多用户加入（后续版本）
- 数据模型预留user_id字段
- 不实现权限系统，后续可扩展

## 3. 项目管理

### 3.1 项目状态

| 状态 | 说明 |
|------|------|
| active | 进行中 |
| paused | 暂停 |
| completed | 已完成 |
| archived | 已归档 |

### 3.2 项目结构

```
Project
├── 基本信息（名称、描述、封面、标签）
├── 状态
├── Agents[]（项目级Agent池，引用全局Agent + 项目级配置）
├── Global Resources（全局共享资料）
├── Groups[]（群聊，有序）
└── Workflow（工作流配置）
```

| 操作 | 说明 |
|------|------|
| 创建 | 新建项目，设置基本信息 |
| 编辑 | 修改项目信息、状态 |
| 复制 | 复制项目结构（可选择性复制内容） |
| 导出 | 选择性导出项目内容为文件 |
| 导入 | 从文件导入项目 |
| 删除 | 删除项目（需确认） |

### 3.4 导出/导入

**导出选项**：
- [ ] 项目基本信息

- [ ] 群聊结构（群聊列表、任务列表）

- [ ] 群聊资料

## 4. Agent管理

### 4.1 Agent层级

```
Global Agent（全局）
├── 基本定义（名称、角色、描述）
├── System Prompt
├── Tools（绑定工具）
├── Skills（技能）
├── Capabilities（能力描述）
└── Config（模型配置等）

Project Agent（项目级）
├── 引用全局Agent
├── Project-specific Notes（项目级个人笔记）
└── 项目内覆盖配置（可选）
```

### 4.2 Agent定义

| 字段 | 说明 |
|------|------|
| name | Agent名称 |
| role | 角色类型（writer/critic/researcher/planner/editor/custom） |
| description | 描述（给其他Agent和用户看） |
| system_prompt | 系统提示词 |
| tools | 绑定的工具列表（可调用的外部工具） |
| skills | 技能定义（可复用的能力模块） |
| capabilities | 能力描述文本 |
| model_config | 模型配置（模型选择、温度等） |

### 4.3 Agent参与规则

- 一个Agent可以被邀请到不同群聊
- **同一时刻，一个Agent只能在一个群聊中活跃工作**
  - 正在回复或调用工具时，不能同时在另一个群聊工作
  - 避免个人笔记写入冲突
- Agent在项目中的个人笔记是**项目级**的，跨群聊共享

### 4.4 Agent详情查看

在群聊中点击Agent可查看：
- 基本信息（名称、角色、描述）
- System Prompt（可展开查看）
- 绑定工具列表（点击可查看工具详情）
- Skill列表（点击可查看skill详情）
- 在本项目中的参与情况

### 5.4 群聊操作

|------|------|

| 添加Agent | 邀请Agent加入群聊 |
| 移除Agent | 从群聊移除Agent |
| 状态变更 | 手动变更群聊状态 |

### 5.5 群聊内可查看信息

| 信息 | 说明 |
|------|------|
| 聊天记录 | 群聊内所有消息历史 |
| 群聊资料 | 群聊级别的共享资料 |
| 任务列表 | 群聊内的任务及状态 |
| 成员Agent | Agent列表，点击查看详情 |

├── Status（todo/in_progress/done/reopened）

### 6.2 任务状态

| 状态 | 说明 |
|------|------|
| todo | 待开始 |
| in_progress | 进行中 |
| done | 已完成 |
| reopened | 重新打开 |

### 6.3 任务执行

- 任务按顺序执行（当前版本）
- 预留并行执行扩展（二维列表/依赖关系）
- 任务可重新打开，重新讨论
- 任务完成需通过验收（见讨论流程）

### 6.4 任务操作

| 操作 | 说明 |
|------|------|

| 开始 | 开始任务，创建讨论链 |
| 重新打开 | 将已完成任务重新打开 |
| 完成 | 标记任务完成 |

## 7. 讨论流程

### 7.1 链（Chain）机制

```
Chain（讨论链）
├── Task（关联任务）
├── Participants[]（参与Agent）
├── Messages[]（消息记录）
├── Status（active/completed）
└── Context Snapshot（上下文快照）
```

**一个Chain对应一个任务**，是Agent讨论的载体。

### 7.2 讨论流程

```
1. 创建任务（设置标题、描述、验收标准、指派Agent）
2. 创建Chain
3. 主导Agent引导讨论
4. 参与Agent发言（主导Agent决定谁发言）
5. 用户可观察/介入
6. 达成共识 → 生成交付物
7. 各Agent整理个人笔记
8. 任务完成
```

### 7.3 Agent发言机制

- **自由调度**：主导Agent自行决定谁发言
- 通过提示词引导流程，不硬编码发言顺序
- 用户可在任务描述、验收标准中引导流程

### 7.4 用户介入

**用户发言规则**：
- 用户不能在Agent输出时直接发言
- 用户可停止当前讨论后再发言

**停止方式**：
| 方式 | 说明 |
|------|------|
| 等待完成 | 等当前Agent输出完成后停止 |
| 任务结束 | 等当前任务结束后停止 |
| 强制停止 | 立即停止，当前输出不计入历史 |

**用户介入后**：
- 可以补充信息、纠正方向
- Agent会看到用户的消息并据此调整

### 7.5 共识判断

**验收机制**：

1. **用户定义验收标准**：创建任务时可写明验收要求
2. **检视Agent**：可单独加入评分/检视Agent判断是否满足要求

**主导Agent职责**：
- 引导讨论方向
- 判断何时达成共识
- 决定是否需要更多讨论
- 触发验收检查
- 生成交付物

### 7.6 发言规则

- **同一时刻只有一个发言者**（Agent或用户）
- 不需要实时打字状态显示
- 当前发言者完成后，下一个发言者开始

## 8. 交付物系统

### 8.1 交付物结构

```
Deliverable（交付物）
├── Title（标题）
├── Type（类型，标签方式）
├── Content（内容，Markdown格式）
├── Tags[]（标签）
├── Metadata（元数据）
├── Version（版本号）
├── Chain ID（关联的讨论链）
├── Group ID（所属群聊）
├── Author（主导生成的Agent）
└── Participants[]（参与的Agent）
```

### 8.2 交付物类型

**类型通过标签自定义**，不硬编码。

**标签管理（项目级独立）**：
- 每个项目独立管理自己的标签体系
- 新增标签时需在项目标签管理区说明：
  - 标签名称
  - 标签用途说明
  - 建议的格式/模板（可选）
- 目的：统一命名、方便检索、可针对标签定制提示词/skill

**标签管理界面**：
- 项目内可查看所有已定义标签
- 可新增、编辑、删除标签
- 删除标签时检查是否有关联交付物

**示例标签**（以小说项目为例）：
| 标签 | 说明 |
|------|------|
| outline | 故事大纲 |
| worldbuilding | 世界观设定 |
| character | 人物设定 |
| chapter | 章节内容 |
| review | 评审意见 |

### 8.3 交付物操作

| 操作 | 说明 |
|------|------|
| 创建 | Agent生成或用户手动创建 |
| 编辑 | 修改内容（支持迭代） |
| 版本管理 | 记录版本历史，支持对比 |
| 查看 | Markdown渲染为友好展示 |
| 引用 | 其他任务/群聊可引用此交付物 |

### 8.4 交付物归属

- 群聊中间产物 → 群聊级共享
- 群聊最终交付物 → **项目级共享**（自动提升）

## 9. 资料体系

### 9.1 资料层级

```
Project
├── Global Resources（全局资料）
│   ├── 用户手动添加
│   ├── Agent添加
│   └── 群聊交付物（自动成为项目级）
│
├── Group Resources（群聊资料）
│   ├── 群聊中间产物
│   ├── 用户手动添加
│   └── Agent添加
│
└── Agent Memory（个人笔记）
    └── 每个Agent在项目中的积累
```

### 9.2 资料属性

| 属性 | 说明 |
|------|------|
| title | 标题 |
| content | 内容（Markdown） |
| type | 类型（note/reference/guideline/rule） |
| scope | 作用域（global/group） |
| required | 是否必读 |
| tags | 标签 |
| created_by | 创建者（user/agent_name） |
| created_at | 创建时间 |
| updated_at | 更新时间 |

### 9.3 必读资料

- 标记为`required`的资料会被默认加入所有Agent上下文
- 适用于：项目规则、共识标准、基本设定等

### 9.4 Agent读取资料

- 默认：按需检索（Agent自己决定看什么）
- 必读资料：自动注入上下文
- 系统不做内容过滤，全量提供给Agent

### 9.5 资料操作

| 操作 | 说明 |
|------|------|
| 添加 | 用户或Agent添加资料 |
| 编辑 | 修改资料内容 |
| 删除 | 删除资料 |
| 标记必读 | 设置为必读资料 |
| 查看 | Markdown渲染展示 |

## 10. Agent个人笔记

### 10.1 笔记特性

- **项目级**：Agent在某个项目中的积累
- **跨群聊共用**：在不同群聊中都可使用
- **不属于交付物**：是Agent的知识积累
- **用户可见**：用户可查看所有Agent的个人笔记

### 10.2 笔记结构

```
Agent Memory（个人笔记）
├── Agent ID
├── Project ID
├── Content（Markdown格式）
├── Tags[]（标签，方便检索）
└── Updated At
```

### 10.3 笔记使用场景

- Agent加入新群聊时，个人笔记作为上下文一部分
- Agent讨论时参照笔记，发现冲突可提出
- 任务完成后，Agent整理本次讨论的收获写入笔记
- 用户可查看Agent笔记，了解Agent的积累和思考

### 10.4 笔记查看

**用户视角**：
- 可在Agent详情页查看该Agent在各项目的笔记
- 可在项目内查看所有Agent的笔记
- 笔记以Markdown渲染展示

**查看入口**：
- Agent详情页 → 项目笔记列表
- 项目资料区 → Agent笔记列表
- 群聊成员 → 点击Agent → 查看笔记

### 10.5 冲突处理

- Agent发言时会参照个人笔记
- 如果发现与当前讨论内容冲突，可以提出：
  > "根据我之前的记录...，这里似乎与当前讨论有矛盾"
- 由主导Agent或用户决定如何处理

## 11. 工作流

### 11.1 工作流概念

工作流是群聊执行顺序的可视化。

### 11.2 工作流特性

- **简单为主**：主要是群聊排序，顺序执行
- **支持并行**：预留并行能力（后续扩展）
- **可动态调整**：随时添加新群聊/任务
- **可导入导出**：随项目一起导入导出

### 11.3 工作流视图

```
[群聊1: 大纲] ──→ [群聊2: 设定] ──→ [群聊3: 细纲] ──→ [群聊4: 章节]
    ✓                 ✓                 ○                 ○
```

- 展示群聊顺序和状态
- 可点击跳转到群聊
- 可拖拽调整顺序
- 可设置自动推进

### 11.4 自动推进设置

用户可为每个群聊设置完成后行为：
- 自动推进到下一个群聊
- 完成后等待用户审核

## 12. 通知与状态

### 12.1 通知方式

- 群聊红点显示有新消息
- 不做过度推送（无浏览器推送、无邮件）

- 用户离线不影响Agent工作
- FULL_AUTO模式：继续执行
- SEMI_AUTO模式：遇到需要决策的暂停等待

## 15. 交互细节

### 15.1 群聊内交互

**消息类型**：
- Agent消息（带头像、名称、角色标识）
- 用户消息
- 系统消息（任务状态变更、Agent加入/离开等）

**系统消息样式**：
- 单行居中显示，小字体
- 浅色背景或虚线边框
- 不占用过多空间
- 示例：
  ```
  ── Agent「梦笔生花」加入了群聊 ──
  ── 任务「制定三幕结构」已完成 ──
  ── 用户暂停了讨论 ──
  ```

**消息操作**：
- 引用回复（可选）
- 查看消息详情

**右侧面板**：
- 任务列表（可创建、编辑、状态变更）
- 成员Agent列表（可查看详情、邀请/移除）
- 交付物列表（可点击查看）

**左侧面板**：
- 群聊列表（可切换）
- 群聊资料

### 15.2 任务详情

点击任务可查看：
- 任务信息（标题、描述、状态）
- 验收标准
- 指派的Agent
- 讨论链（可展开查看对话）
- 交付物（可点击查看）

### 15.3 Agent详情

点击Agent可查看：
- 基本信息（名称、角色、描述）
- System Prompt（可展开查看）
- 绑定工具列表及详情
- Skill列表及详情
- 项目中的参与情况
- 个人笔记列表（用户可见）

## 16. 文档渲染展示模块

### 16.1 概述

独立的文档渲染展示模块，用于将Markdown内容渲染为人类友好的展示形式。

### 16.2 使用场景

| 场景 | 说明 |
|------|------|
| 交付物查看 | 查看任务产出的交付物 |
| 资料查看 | 查看项目/群聊资料 |
| Agent笔记查看 | 查看Agent个人笔记 |
| 消息内容渲染 | 群聊消息中的Markdown渲染 |

### 16.3 渲染功能

**基础渲染**：
- 标题层级（H1-H6）
- 段落、列表（有序/无序）
- 粗体、斜体、删除线
- 代码块（语法高亮）
- 表格
- 引用块
- 分割线
- 图片（支持本地和远程）
- 链接

**高级功能**：
- 目录导航（根据标题自动生成）
- 任务列表（checkbox）
- 脚注
- 数学公式（KaTeX）
- Mermaid图表（可选）

### 16.4 交互功能

| 功能 | 说明 |
|------|------|
| 目录导航 | 侧边或顶部目录，点击跳转 |
| 全屏模式 | 全屏阅读 |
| 搜索 | 文内搜索 |
| 引用跳转 | 点击引用可跳转到源交付物 |
| 版本对比 | 对比不同版本的差异 |
| 导出 | 导出为PDF/HTML |

### 16.5 版本对比

- 交付物支持多版本
- 可选择两个版本进行diff对比
- 高亮显示新增、删除、修改内容
- 支持逐行对比或并排对比

### 16.6 引用机制

- 交付物中可引用其他交付物
- 引用格式：`[[deliverable:id]]` 或 `[链接文本](deliverable:id)`
- 点击引用可跳转到被引用的交付物
- 悬浮预览（可选）

- 所有文本内容使用**Markdown格式**

- 前端渲染为人类友好展示
